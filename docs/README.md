# Documentation

Start with the [README](../README.md) in the repository root: what SiteTriage does, how to run it
and why its thresholds are what they are. This folder holds the rest.

| Path | What it is |
|---|---|
| [adr/](adr/README.md) | Architecture decision records: one decision each, with its context and consequences. The index lists them all. |
| [adr/legacy-references.md](adr/legacy-references.md) | Decodes the specification, requirement, bug and observation ids that older code comments and the Serbian documents cite. |
| [real-site-verification.md](real-site-verification.md) | Procedure for checking the tool against real sites before a release that changes fetching, level 2 or thresholds. |
| [manual-check-form.md](manual-check-form.md) | Empty form for the manual acceptance check of the top 10 and bottom 5 of a ranking. |
| [sr/](sr/README.md) | Historical documents in Serbian: the test plan, three test reports, the calibration log and a quality review of v1 and v2. |
| [sample-report.html](sample-report.html) | A sample HTML report produced from the hand-written test set, in English, without a profile. |
| [report.png](report.png) | Screenshot of that report, used in the README. |
| [sample-report-sr.html](sample-report-sr.html) | The same test set with the `rs` profile: Serbian report and the Serbian language check. |
| [report-sr.png](report-sr.png) | Screenshot of the Serbian report. |

Contributor guidance is in [CONTRIBUTING.md](../CONTRIBUTING.md), release notes in
[CHANGELOG.md](../CHANGELOG.md), and the vulnerability reporting policy in
[SECURITY.md](../SECURITY.md).
